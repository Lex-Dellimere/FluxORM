`reach/migration/version.mettle`

```mettle
export const RC_MIG_LEDGER: string = "_reach_migrations";

export struct RcMigration { version: int64; name: string; up_sql: string; }
export struct RcMigrationSet { items: RcMigration*; n: int32; }
export struct RcMigrationReport {
  applied: int32;         // applied by this run
  up_to: int64;           // highest version applied after this run
  failed_version: int64;  // 0 when no failure
  code: int32;            // failing RC_*, RC_OK on success
}

export fn rc_migration_set(items: RcMigration*, n: int32) -> RcMigrationSet
export fn rc_migration_check(s: RcMigrationSet) -> int32
export fn rc_migration_ledger_ddl(b: RcBuf*) -> int32
export fn rc_migration_ledger_select(b: RcBuf*) -> int32
export fn rc_migration_ledger_insert(b: RcBuf*) -> int32
export fn rc_migration_now_micros() -> int64
export fn rc_migration_set_clock(us: int64)
export fn rc_migration_run(a: RcAdapter*, s: RcMigrationSet*, out: RcMigrationReport*) -> int32
export fn rc_migration_down(a: RcAdapter*, s: RcMigrationSet*, version: int64) -> int32
```

That is the whole surface — no other export exists in either file. Private
helpers: `rc_migration_affinity` (ddl), `rc_mig_index_of`, `rc_mig_has`,
`rc_mig_apply` (version).

`rc_migration_create_table` takes `RcBuf*` and returns `RC_*` (the directive's
shape). It appends to the caller's buffer and never clears it; `rc_buf_text`
gives the borrowed view.

`rc_migration_down` returns `RC_ERR_UNSUPPORTED` and performs no exec. Up-only
until dacor's catalog is readable: without a catalog a rollback can only guess,
and an unattended guessed `DROP` is a data-loss bug.

`rc_migration_create_table(doc_meta(), b)` → `RC_ERR_UNSUPPORTED`, buffer length
`0` (nothing written). `Doc` carries `uint8[]` → `RC_T_UNSUPPORTED`, refused by
`rc_meta_check` before the builder writes a byte; a field whose affinity is
unknown is refused by the pre-scan for the same reason.

Affinity: `RC_T_I64`/`RC_T_BOOL`/`RC_T_TIME`/`RC_T_U64` → `INTEGER`,
`RC_T_F64` → `REAL`, `RC_T_TEXT` → `TEXT`, `RC_T_BLOB` → `BLOB`,
`RC_T_UNSUPPORTED` → refuse. `RC_F_AUTO` adds no keyword: `INTEGER PRIMARY KEY`
is the whole story (comment in `ddl.mettle`).

## 4. `rc_migration_run` — sequence and exec counts

1. `rc_migration_check(*s)`. Malformed → `out->code`, `applied == 0`, **zero
   execs**.
2. `exec` ledger DDL — no transaction.
3. `exec` ledger SELECT — column 0 of each row read as `int64`; `n_rows == 0`
   is normal, a non-empty result with `n_cols != 1` is `RC_ERR_ADAPTER`.
4. A ledger version absent from the set → `RC_ERR_CONFLICT`,
   `out->failed_version` = that version, no transaction started.
5. Per missing version, ascending: `begin(RC_TX_IMMEDIATE)` → `exec(up_sql)` →
   `exec(ledger INSERT)` with `RcInt(version), RcText(name), RcTime(applied_at)`
   → `commit`. One transaction per migration.
6. Any failure inside the transaction: `rollback`, `out->code` /
   `out->failed_version` set, `out->applied` = how many did apply, return the
   code. The run stops; it does not continue.
7. Success: `out->code = RC_OK`, `failed_version = 0`, `up_to` = highest version
   now applied.

| scenario | execs | commits | rollbacks |
|---|---|---|---|
| set {1,2}, ledger {1} | 4 (DDL, SELECT, up2, INSERT2) | 1 | 0 |
| set {1,2}, ledger {} | 6 (DDL, SELECT, (up,INSERT)×2) | 2 | 0 |
| second run, ledger {1,2} | 2 (DDL, SELECT) | 0 | 0 |
| set {1,2}, ledger {9} | 2 (DDL, SELECT) | 0 | 0 → `RC_ERR_CONFLICT` |
| malformed set | 0 | 0 | 0 |
| failure in up1 (ledger {}) | 3 attempted (DDL, SELECT, up1) | 0 | 1 |

The call counts above are asserted in the test, not estimated: `4`, `6`, `8`,
`2`, `0`.

## 5. Clock decision

**Shipped shape: injected-only.** `rc_migration_set_clock(us)` supplies the
value the ledger uses; `rc_migration_now_micros()` returns it when non-zero and
`0` otherwise. No test depends on wall time — the tests assert
`RcTime(1700000000000123)`.

Justification, probed on mettle 0.17.0 before deciding:

```
$ mettle test /tmp/migprobe/clock.mettle
test t_clock ... skipped (calls C function 'clock_gettime'; the interpreter cannot - run it natively via a main() + --build)
0 passed, 1 skipped
```

`clock_gettime` (the `std/bench.linux` shape) works in debug and release but
makes the compile-time interpreter **skip the entire test file**. A silently
skipped interpreter gate is worse than a zero timestamp, so the extern was not
shipped. The application owns the clock and calls `rc_migration_set_clock`
once per run; the seam is documented at the function and here.

## 8. Findings

1. **Directive keyword order contradicts its own verbatim text.** The prose says
   column = column, affinity, ` PRIMARY KEY`, ` UNIQUE`, ` NOT NULL`; the
   asserted User string is `"email" TEXT NOT NULL UNIQUE`. The verbatim strings
   are what the directive says to assert, so `ddl.mettle` emits `NOT NULL`
   before `UNIQUE` and the comment there records the conflict. If the prose
   order is what was intended, the expected strings in the directive are wrong,
   not the code.
2. **`rc_mem_fail_next` cannot fail "the first pending migration".** `mem`'s
   arming is one-shot and fires on the *next* `exec`, which in this sequence is
   the ledger DDL — so the directive's failure test as written would exercise
   the pre-transaction path, not the rollback path. No frozen file was edited.
   The test does both: (a) plain `rc_mem_fail_next` before the run, proving a
   failure before any transaction leaves no tx state; (b) a test-local vtable
   that is a *copy* of the mem adapter with `exec` replaced by a counter, which
   arms `rc_mem_fail_next` on exec 3 (the migration's `up_sql`). The failure is
   still mem's; only the timing is supplied. A seam change would be
   `rc_mem_fail_at(n, code)` in `adapter/mem.mettle` — reported, not made.
3. **No real clock in the interpreter.** See §5: `extern clock_gettime` makes
   `mettle test` skip the file, so the injected-only shape shipped.
4. The agent brief's `rc_migration_create_table(m) -> string` and
   `rc_migration_run(adapter, set) -> int32` were superseded by the directive's
   `RcBuf*`/`RcMigrationReport*` shapes, which is what is implemented.
5. `docs/02-seams.md` sketches the ledger as
   `(version INTEGER PRIMARY KEY, name TEXT, applied_at INTEGER)`; the
   directive's verbatim DDL adds `NOT NULL` to `name` and `applied_at`. The
   directive's text ships (it is stricter and is the asserted string). No doc
   edit was made.

## 9. Residual risks

- `applied_at` is `0` unless the application injects a clock. That is a
  documented seam, not an accident, but a caller that forgets
  `rc_migration_set_clock` gets a ledger with no timestamps.
- The ledger read assumes the store returns `version` as an integer; a driver
  that returns it as TEXT is `RC_ERR_ADAPTER` via `rc_result_i64`, not a
  coercion.
- Down migrations remain unsupported by design; nothing here can undo a DDL.
- `rc_migration_run` is not re-entrant on one adapter (it holds a transaction
  per migration); a second concurrent run is the store's problem, not this
  module's.
